# Sh.M V2Ray

پروژهٔ بسیار ساده و کاملاً استاتیک برای ارائهٔ **سابسکریپشن V2Ray** روی **GitHub Pages**.

- فقط HTML + CSS + JavaScript
- بدون سرور، بدون Cloudflare Workers، بدون دیتابیس
- بدون ثبت‌نام، بدون تایمر، بدون انقضای اشتراک
- رایگان و قابل انتشار روی GitHub Pages

---

## ساختار فایل‌ها

```
Sh.M-V2Ray/
├── index.html      ← صفحه اصلی و رابط کاربری
├── style.css       ← طراحی دارک، راست‌چین و واکنش‌گرا
├── script.js       ← منطق خواندن کانفیگ و ساخت Base64
├── configs.txt     ← لیست کانفیگ‌ها (هر خط یک کانفیگ)
├── sub             ← فایل سابسکریپشن Base64 (باید خودتان بسازید)
└── README.md       ← همین راهنما
```

---

## چگونه کار می‌کند؟

1. تمام کانفیگ‌ها داخل فایل `configs.txt` نوشته می‌شوند.
   می‌توانید هر کانفیگ را در چند خط بنویسید؛ فقط بین کانفیگ‌ها **یک خط خالی** بگذارید.
2. سایت این فایل را می‌خواند، کامنت‌ها (`#`) را حذف می‌کند و خطوط داخل هر بلوک را به هم می‌چسباند.
3. محتوای باقی‌مانده را با فرمت استاندارد سابسکریپشن (متن Base64‌شده) آماده می‌کند.
4. شما می‌توانید:
   - محتوای Base64 را کپی کنید، یا
   - فایل `sub` را دانلود کنید و در مخزن قرار دهید.
5. لینک دائمی سابسکریپشن این است:

```
https://raw.githubusercontent.com/USERNAME/REPO/main/sub
```

کلاینت‌های V2Ray مستقیماً این لینک را می‌گیرند و کانفیگ‌ها را دریافت می‌کنند.

> **نکته فنی:** چون GitHub Pages فقط فایل‌های استاتیک میزبانی می‌کند، لینک واقعی سابسکریپشن باید به یک فایل ثابت (`sub`) اشاره کند. هر بار که `configs.txt` را تغییر می‌دهید، باید فایل `sub` را هم به‌روزرسانی کنید.

## مراحل انتشار رایگان روی GitHub Pages

### ۱. ساخت مخزن جدید

1. وارد [GitHub](https://github.com) شوید.
2. روی **New repository** کلیک کنید.
3. نام مخزن را مثلاً `Sh.M-V2Ray` بگذارید.
4. مخزن را **Public** انتخاب کنید (برای GitHub Pages رایگان لازم است).
5. گزینهٔ Initialize با README را اگر خواستید بزنید یا نزنید.
6. **Create repository** را بزنید.

### ۲. آپلود فایل‌ها

یکی از دو روش زیر را انتخاب کنید:

**روش آسان (از طریق وب):**
1. وارد مخزن شوید.
2. روی **Add file → Upload files** کلیک کنید.
3. تمام فایل‌های پروژه (`index.html`, `style.css`, `script.js`, `configs.txt`, `README.md`) را بکشید و رها کنید.
4. **Commit changes** را بزنید.

**روش با Git (پیشنهادی برای آپدیت‌های بعدی):**
```bash
git clone https://github.com/YOUR_USERNAME/Sh.M-V2Ray.git
cd Sh.M-V2Ray
# فایل‌ها را کپی کنید
git add .
git commit -m "اولین نسخه Sh.M V2Ray"
git push origin main
```

### ۳. فعال‌سازی GitHub Pages

1. در مخزن به **Settings → Pages** بروید.
2. در بخش **Source** گزینهٔ **Deploy from a branch** را انتخاب کنید.
3. Branch را روی `main` (یا `master`) و پوشه را روی `/ (root)` بگذارید.
4. **Save** را بزنید.
5. بعد از حدود ۱ تا ۲ دقیقه، سایت شما در آدرس زیر در دسترس است:

```
https://YOUR_USERNAME.github.io/Sh.M-V2Ray/
```

### ۴. اضافه کردن کانفیگ‌ها

1. فایل `configs.txt` را باز کنید.
2. کانفیگ‌ها را پیست کنید. می‌توانید هر کانفیگ را در چند خط بنویسید؛ فقط بین دو کانفیگ **یک خط خالی** بگذارید. مثال:

```
vmess://eyJ2IjoiMiIsInBzIjoiVGVzdCJ9

vless://uuid@server.example.com:443?encryption=none&security=tls&type=ws&path=%2F#MyServer

trojan://password@server.example.com:443?security=tls#Trojan1

ss://YWVzLTI1Ni1nY206cGFzc3dvcmQ@server.example.com:8388#SS1
```

3. خطوطی که با `#` شروع می‌شوند نادیده گرفته می‌شوند (مناسب برای توضیح).
4. تغییرات را Commit و Push کنید.

### ۵. ساخت و به‌روزرسانی فایل `sub` (لینک دائمی)

1. سایت را باز کنید: `https://YOUR_USERNAME.github.io/Sh.M-V2Ray/`
2. روی دکمه **⬇️ دانلود فایل sub** کلیک کنید (یا Base64 را کپی کنید).
3. فایل دانلودشده را با نام دقیقاً `sub` (بدون پسوند) در ریشهٔ مخزن قرار دهید.
4. Commit و Push کنید.

حالا لینک سابسکریپشن شما این است:

```
https://raw.githubusercontent.com/YOUR_USERNAME/Sh.M-V2Ray/main/sub
```

این لینک را در کلاینت‌هایی مثل **v2rayNG**، **Streisand**، **Hiddify**، **V2Box** و ... وارد کنید.

### ۶. هر بار که کانفیگ جدید اضافه می‌کنید

1. `configs.txt` را ویرایش و Push کنید.
2. صفحهٔ سایت را رفرش کنید.
3. دوباره فایل `sub` را دانلود (یا Base64 را کپی) کنید.
4. فایل `sub` قدیمی را با نسخهٔ جدید جایگزین و Push کنید.

## استفاده در کلاینت

1. لینک `https://raw.githubusercontent.com/USERNAME/REPO/main/sub` را کپی کنید.
2. در کلاینت به بخش **Subscription** / **سابسکریپشن** بروید.
3. لینک را Paste کنید و **Update** بزنید.
4. کانفیگ‌ها ظاهر می‌شوند.

## عیب‌یابی

| مشکل | راه‌حل |
|------|--------|
| صفحه خطای «فایل configs.txt یافت نشد» می‌دهد | مطمئن شوید فایل در ریشهٔ مخزن و کنار `index.html` است. |
| تعداد کانفیگ صفر است | بین کانفیگ‌ها خط خالی بگذارید. خطوط `#` نادیده گرفته می‌شوند. حداقل یک کانفیگ واقعی اضافه کنید. |
| لینک سابسکریپشن در کلاینت کار نمی‌کند | فایل `sub` را ساخته و Push کرده‌اید؟ نام فایل دقیقاً `sub` باشد (بدون `.txt`). |
| بعد از تغییر configs لینک قدیمی است | فایل `sub` را دوباره از سایت دانلود و جایگزین کنید. |

## نکات مهم

- این پروژه **هیچ سرور یا سرویسی** اضافه نمی‌کند و کاملاً روی GitHub Pages اجرا می‌شود.
- فایل `sub` باید به‌صورت دستی (یا با اسکریپت محلی خودتان) همگام با `configs.txt` نگه‌داری شود.
- برای امنیت بیشتر می‌توانید مخزن را Private کنید، اما در این صورت GitHub Pages برای حساب‌های رایگان در دسترس نیست (نیاز به GitHub Pro دارد).
- کانفیگ‌های حساس را فقط در مخزن‌هایی قرار دهید که به آن‌ها اعتماد دارید.
